## Summary

Adds an **API key** authentication option. HomeBox issues long-lived static API keys (Profile → API tokens) that are accepted directly as the `Authorization` value, so a username/password login round-trip isn't required. Users can now authenticate the integration with a key instead of storing their HomeBox password.

## What changed

- **Config flow** now opens with a menu to pick the auth method, then shows a dedicated form for each so only the relevant fields are requested:
  - **API key** → host, API key, name, room
  - **Email & password** → host, username, password, name, room (unchanged behaviour)
- **api.py**: `async_authenticate_with_api_key()` stores the key as the token and verifies it with a lightweight authenticated request.
- **coordinator.py**: authenticates via API key when configured, otherwise falls back to username/password.
- **strings/en**: menu options, per-method field descriptions, reworded auth-failure copy.

Fully backward compatible — existing username/password entries keep working unchanged.

## Testing

- Set up a fresh entry via the **API key** path against HomeBox v0.26.2: authenticates with no login call, statistics sensors populate, tagged items load.
- Confirmed the entry stores only `api_key` (no password) and reloads cleanly.
- JSON translations validated.
